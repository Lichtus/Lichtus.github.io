CV Fit Analyzer

Source code on GitHub ↗

A CV generator tailored to a specific job ad — with a score telling you whether applying is worth it at all, and a hard ban on crediting the candidate with skills they do not have.

The problem

Tailoring a CV to an ad takes an hour: pull out the requirements, pick the matching experience, rewrite the bullets, format the document. Across twenty applications — a week. LLM-based generators do it in a minute, but carry a disqualifying flaw: they invent skills, because it makes the match look better. A CV like that stops working at the first interview.

A ban on fabrication

The job ad is a selection filter, not a source of content. It decides which real experiences to show and in which language — never what the CV claims. The prompt is forbidden from copying keywords out of the ad into the skills and bullets, and from inventing numbers.

The data that must not be paraphrased — name, contact details, education, courses, languages — bypasses the model entirely and goes into the document straight from the profile file. The importer works the same way in reverse: it transcribes, it does not write. A missing value is an omitted field, never a guess.

Pipeline

Analyse the ad→ Score the fit→ Generate the CV

The third step only runs above a score threshold, so weak ads cost no tokens. The scoring returns a result together with strengths and gaps, which also answers the question of whether applying makes sense.

Features

  • Four formats — an HTML report with the score, a DOCX reproduced pixel-for-pixel from a master file, an HTML CV laid out for A4 printing, and a PDF via headless Chrome
  • Universal mode — a general CV with no job ad, one call instead of three, cached
  • CV import — PDF sent natively to the model, DOCX and plain text handled locally; the result lands in the form, not straight on disk
  • Candidate profiles — one file per person, an automatic backup before every save, a bin for deleted ones
  • Three languages — a CV in Polish, English or German depending on the ad, with CEFR levels and per-language grammar rules for the bullets; interface in PL/EN
  • Data editor — a validated form, with the photo embedded as a data URI, so a single JSON holds the complete dataset
  • Run history — a companion file recording the role, the score and the language

Models and API keys

Four models from two providers (Gemini 2.5 Flash and Pro, GPT-4o, GPT-4o mini), selected from the sidebar. Adding a provider means one module satisfying a six-part contract — the registry, the retry logic and key handling are shared.

Clients are built lazily, so a clone with no keys at all starts up normally. Choosing a model without a key brings up a one-off form; the key goes into .env with 600 permissions and takes effect without a restart. A key rejected by the API comes back through the same path.

Retries: up to five attempts with exponential backoff, for transient errors only. Candidate data, backups and keys stay local, outside the repository.

Solutions worth a mention

A cache keyed by a hash of the data

The universal CV does not depend on any job ad, so it is rebuilt without calling the model — roughly 20,000 fewer tokens per run. The key is a checksum of the candidate's data, so any edit invalidates the entry by itself; nothing in the code has to remember to clear it.

Generation counters in widget keys

Streamlit ignores a field's initial value once its key already exists in the session — after switching profiles the form still showed the previous name, and a new profile could be saved carrying the previous candidate's data. A generation counter in the key gives every version of the data its own namespace.

PDF through headless Chrome

Chrome writes the document in a second, then hangs on updater tasks. Rather than waiting for a clean exit, the function polls the output file until it stops growing, then terminates the process.
